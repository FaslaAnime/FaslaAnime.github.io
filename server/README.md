# سيرفر التراخيص والأدمن — مصري / Masry (نسخة محلية)

> للنشر على GitHub Pages استخدم [`worker/README.md`](../worker/README.md).
> هذا السيرفر مخصص للتشغيل على جهازك أو VPS.

سيرفر Node بلا أي مكتبات خارجية (`node server.js` بس). بيعمل ثلاث حاجات:

1. يقدّم ملفات الموقع الثابت من جذر الريبو.
2. يقدّم لوحة الأدمن من `/admin/` (ملفاتها في جذر الريبو، مشتركة مع نسخة Pages).
3. (API) تسجيل الأجهزة وفحص التراخيص وإبطالها.

## التشغيل

```bash
cd server
npm start          # أو: node server.js
```

أول تشغيل بدون `ADMIN_PASSWORD` بيتولّد كلمة مرور عشوائية وتُطبع في الشاشة وتُحفظ في `data.json`.
انتبه لها، أو اضبط البيئة قبل التشغيل:

```powershell
$env:ADMIN_PASSWORD="اختر-كلمة-قوية"
node server.js
```

افتح:

- الموقع: `http://localhost:8080/`
- الأدمن: `http://localhost:8080/admin/`

## المتغيرات

| المتغير | الافتراضي | الوظيفة |
| --- | --- | --- |
| `PORT` | `8080` | رقم البورت |
| `HOST` | `0.0.0.0` | عنوان الربط |
| `ADMIN_PASSWORD` | (تُولّد) | كلمة مرور الأدمن |
| `WATERMARK` | `sistro` | العلامة المعروضة على الجهاز |
| `OWNER` | `Mohamed_0_9` | اسم المالك تحت العلامة |
| `TRIAL_DAYS` | `3` | مدة التجربة للجهاز الجديد |
| `DATA_FILE` | `server/data.json` | مسار ملف البيانات |

## تدفق الترخيص

1. المستخدم يفتح الهوست (`dev/index.html`). `license.js` يولّد `masry_device_id` في `localStorage` ويرسله لـ `POST /api/v1/license`.
2. السيرفر يسجّل الجهاز (أو يحدّث آخر ظهور) ويرجع الحالة: `active` / `trial` / `expired` / `revoked` + تاريخ الانتهاء + العلامة.
3. الزر يبقا مقفول إلا لو الحالة `active` أو `trial`. «منتهي» أو «مُبطَل» يظهروا كرسالة تجديد.
4. الأدمن يشوف الجهاز في اللوحة ويضغط «تفعيل 30 يوم» بعد استلام الدفع.
5. لو القررت «إبطال»، الزر يقفل فوراً من أي فتحة جديدة للهوست.

**fail-open:** لو السيرفر مش متاح (مثلاً نسخة GitHub Pages) الصفحة بتعتبر  herself تجربة مفتوحة. لو السيرفر شغال ورجع «منتهي/مُبطَل»، بيتمسك.

## لوحة الأدمن

- إحصائيات: الإجمالي، المُفعّلة، التجربة، المنتهية، المُبطَلة، والظاهرة آخر 24 ساعة.
- جدول كل الأجهزة: الـ ID، النسخة، الحالة، تاريخ الانتهاء، آخر ظهور.
- إجراءات: تفعيل 30 يوم، تمديد 30 يوم، إبطال، إلغاء إبطال، حذف.
- بحث فوري بالـ ID أو النسخة أو الحالة.
- الجلسة تنتهي بعد 12 ساعة، ومحاولات الدخول محدودة (5 في الدقيقة لكل IP).

## API

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `GET` | `/api/v1/config` | العلامة والمالك ومدة التجربة |
| `POST` | `/api/v1/license` | تسجيل/فحص جهاز `{deviceId, firmware, ua}` |
| `POST` | `/api/v1/admin/login` | `{password}` → `{token}` |
| `GET` | `/api/v1/admin/devices` | قائمة الأجهزة (Bearer) |
| `GET` | `/api/v1/admin/stats` | إحصائيات (Bearer) |
| `POST` | `/api/v1/admin/devices/<id>` | `{action: activate\|extend\|revoke\|unrevoke\|delete, days?}` |
| `POST` | `/api/v1/admin/logout` | إنهاء الجلسة |
| `GET` | `/api/v1/blob/<path>?token=` | توصيل `.bin` برمز موقّع |

كل مسارات الأدمن بتطلب `Authorization: Bearer <token>`.

## توصيل البايلود عبر السيرفر (خطوة تقوية اختيارية)

`/api/v1/license` بيرجع `blobToken` موقّع بـ HMAC صالح 10 دقائق للجهاز الصالح فقط.
تقدر توجّه تحميل ملفات `.bin` through:

```
/api/v1/blob/jb/relapse/goldhen.bin?token=<blobToken>
```

ده يمنع 任何 حد من يسحب البايلود مباشرة من الاستاتيك بدون ترخيص ساري. دمجه في السلاسل
المحتوية على AGPL بيتم في طبقة الـ bridge عندك (ملفات `bridge.js` مش ملفات السلسلة نفسها).

## الأمان

- كلمة مرور الأدمن متخزّنة كـ scrypt hash، والمقارنة `timingSafeEqual`.
- جلسات عشوائية في الذاكرة، وتنتهي بعد 12 ساعة.
- حد أقصى 64KB لأي request body، وحد لمحاولات الدخول.
- _headers_: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`.
- كتابة ذرّية لملف البيانات (tmp + rename).
- مسارات الملفات الثابتة بترفض `..` والملفات المخفية ومجلد `server/` و`data.json`.

**مهم:** السيرفر شغال على HTTP صافي. للشفير أثناء النقل لازم تشغّله ورا
 reverse proxy بشهادة (Cloudflare / Nginx + Let's Encrypt). لو الاتصال مشفر، اللي على السلك يبقا مقروء.

## حدود صريحة

- البوابة في الواجهة عائق منطقي، مش «أمن مستحيل»: أي كود client-side ممكن يتخطى لو حد فتح صفحة السلسلة مباشرة.
  علشان كده توصيل البايلود عبر `/api/v1/blob` هو التقوية الحقيقية.
- النظام ده **مفيش فيه أي قدرة مسح أو تعديل محتوى على جهاز المستخدم**. هو بيدير التراخيص بس.
- علامة «sistro» بتظهر في واجهة الهوست (سطر في الفحص + التذييل)، مش في معلومات نظام الجهاز نفسه —
  تعديل معلومات النظام عن بُعد من متصفح مستحيل من غير كتابة على الجهاز، وده outside نطاق النظام.

## النشر

- أي VPS أو جهاز عندك عليه Node ≥ 18: `node server.js` وراء Nginx/Caddy.
- ضبط `PORT` وخلف `HOST=127.0.0.1` لو reverse proxy محلي.
- `data.json` لو اتسرّب مفيش فيه كلمة مرور  plaintext (hash بس)، لكن خزّنه في مكان خاص.
